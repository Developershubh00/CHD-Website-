# CHD Design Pipeline — run playbook

Designers submit designs through a Google Form; approved designs get
published to creativehomedecorllp.com. Two scheduled runs share this
playbook — each run does ONLY its own section.

Daily rhythm (IST): designers submit any time → **9:00 PM intake run**
generates lifestyle images onto the review board → team reviews by
**1:00 PM** next day (STATUS dropdown: APPROVED / REDO + Remarks) →
**1:30 PM publish run** pushes approved designs live; REDO rows are
regenerated by that evening's intake run.

## Intake run (9:00 PM IST)

Generates lifestyle images for new submissions and REDO rows. Does not
need the full repository — only the scripts folder.

1. Attach the repo with `add_repo` (owner `Developershubh00`, repo
   `CHD-Website-`, access `read`), then make a LIGHTWEIGHT clone (the
   full repo is 4GB of images you do not need):
   `git clone --depth 1 --filter=blob:none --sparse <url> chd && cd chd && git sparse-checkout set scripts`
2. Confirm env vars: `CHD_BRIDGE_URL`, `CHD_BRIDGE_TOKEN`,
   `GEMINI_API_KEY`. Missing → STOP and report which.
3. `bun install` then `bun scripts/design-pipeline.mjs intake`
4. If a generation fails, retry once; report persistent failures with the
   style number and verbatim error.
5. The script emails the team the outcome itself (images ready / nothing
   submitted). If it logs "team notification skipped", mention that in
   your report - the bridge deployment is outdated.
6. **If the script prints `intake: NO NEW DESIGNS`** and your instructions
   do NOT say you are the 11:00 AM recheck: schedule a one-off recheck for
   11:00 AM IST the next day so late uploads still make that day's
   1:30 PM publish. Use the claude-code-remote `create_trigger` tool:
   - name: `CHD intake recheck (one-off)`
   - run_once_at: next day at `05:30:00Z` (= 11:00 AM IST)
   - create_new_session_on_fire: true
   - notifications: `{"push": true, "email": true}`
   - prompt: `Follow ONLY the "Intake run" section of
     scripts/design-pipeline-playbook.md in the GitHub repo
     Developershubh00/CHD-Website- (branch main). You are the one-off
     11:00 AM IST recheck: do NOT schedule another recheck, whatever the
     result.`
   Include the trigger id in your final report. If you ARE the recheck,
   never schedule another one - the nightly 9:00 PM run continues on its
   own schedule regardless.

## Publish run (1:30 PM IST)

Publishes board rows whose STATUS is exactly APPROVED and Published is
empty. Needs the full repository.

1. Attach the repo with `add_repo` (access `push`), full clone, `cd` in.
2. `bun install`
3. Confirm env vars: `CHD_BRIDGE_URL`, `CHD_BRIDGE_TOKEN`.
4. `bun scripts/design-pipeline.mjs publish --commit`
   - The script verifies internally (tsc + full build) BEFORE committing
     and refuses to push if verification fails — report such errors
     verbatim, do not work around them.
   - Previously staged slides from an interrupted run are resumed, not
     skipped.

## Rules for both runs

- Never publish a design whose board STATUS is not exactly APPROVED.
- Never edit pipeline scripts, website code, or other products' files.
- The review board is the single source of truth:
  https://docs.google.com/spreadsheets/d/1xfut34jDvryqJd8Rpp7rV71WFUVY7X7pqRu0LfAr3Is
- Final report: short. Styles published / sent for review / redone, and
  failures with exact errors.
