# CHD Design Pipeline — run playbook

Designers submit designs through a Google Form; approved designs get
published to creativehomedecorllp.com. Two scheduled runs share this
playbook — each run does ONLY its own section.

Daily rhythm (IST): designers submit any time → **9:00 PM intake run**
generates lifestyle images onto the review board → **11:00 AM recheck
run** catches anything submitted late → team reviews by **1:00 PM**
(STATUS dropdown: APPROVED / REDO + Remarks) → **1:30 PM publish run**
pushes approved designs live; REDO rows are regenerated by the next
intake or recheck run.

## Where the runs execute

All three daily runs fire into ONE long-lived Claude session that has this
repository checked out at /home/user/CHD-Website- (session
session_01XhBEruJg1fEi4onQ2MS5L6). Fresh scheduled sessions cannot be used:
the sandbox refuses to execute scripts from a freshly cloned repository
("Code from External"), and they have no push credential. The trigger
prompts carry the exact steps; this file is the reference.

## Intake run (9:00 PM IST)

Generates lifestyle images for new submissions and REDO rows.

1. `git fetch origin main`; fast-forward if behind. The tree should be
   clean (a previous publish may have left staged slides - commit or
   stash safely first).
2. Confirm env vars: `CHD_BRIDGE_URL`, `CHD_BRIDGE_TOKEN`,
   `GEMINI_API_KEY`. Missing → STOP and report which.
3. `bun install` only if node_modules is missing or sharp fails to load.
4. `bun scripts/design-pipeline.mjs intake` in the background; monitor to
   completion. Large batches take hours (roughly 2-5 min per design) -
   never stop it early.
5. Per-design `FAILED` lines are normal (retried next run). If the
   process dies before `intake: done`, re-run once.
6. The script emails the team itself: images ready / nothing submitted /
   action needed (bad files, category checks) / billing stopped. If it
   logs "notification skipped", mention that in your report.
7. `intake: STOPPED ... GEMINI_BILLING` means the Gemini project's prepaid
   credits are depleted. Nothing can be generated until the owner tops up
   at https://ai.studio/projects; the script has already emailed. Report
   it plainly - do not retry.

## Recheck run (11:00 AM IST)

Identical to the intake run with ONE difference: run
`bun scripts/design-pipeline.mjs intake --quiet-empty`
(suppresses the "nothing submitted" and billing emails so an empty
morning does not nag twice). Designs submitted overnight are generated
in time for the same day's 1:00 PM review and 1:30 PM publish. It may
still be running when the 1:30 PM publish fires - that is fine.

## Publish run (1:30 PM IST)

Publishes board rows whose STATUS is exactly APPROVED and Published is
empty. Runs in the same long-lived session (which holds push credentials).

1. `git fetch origin main`; the working tree must be clean and up to date
   with origin/main.
2. `bun install` only if node_modules is missing or sharp fails to load.
3. Confirm env vars: `CHD_BRIDGE_URL`, `CHD_BRIDGE_TOKEN`.
4. `bun scripts/design-pipeline.mjs publish --commit`
   - Verifies internally (tsc + full build) BEFORE committing and refuses
     to push if verification fails — report such errors verbatim, do not
     work around them.
   - Previously staged slides from an interrupted run are resumed, not
     skipped; an already-committed-but-unpushed publish is pushed.
   - After a successful push the script emails the team the list of
     styles that just went live (standing rule).
5. Push the working branch too (`git push -u origin
   claude/chdllp-ui-fixes-sync-97ifyg`) so branch and main stay in sync.

## Rules for both runs

- Never publish a design whose board STATUS is not exactly APPROVED.
- A REDO on an already-published design clears its Published stamp; when
  re-approved, the publish run updates the existing product slide in
  place — it never creates a duplicate.
- Standing rule: anything a submission fails on that the TEAM must fix
  (unsupported format, oversized file, missing image) is emailed to them
  automatically by the script with plain-language instructions — never
  rely on run reports alone to tell the team.
- The optional "Back side image" form upload is published AS-IS (never
  generated, never reviewed): it lands as back.png in the product slide
  and the site shows it right after the front image. A broken back
  upload never blocks the product — it publishes without it and the
  team is emailed what to fix.
- Never edit pipeline scripts, website code, or other products' files.
- The review board is the single source of truth:
  https://docs.google.com/spreadsheets/d/1xfut34jDvryqJd8Rpp7rV71WFUVY7X7pqRu0LfAr3Is
- Final report: short. Styles published / sent for review / redone, and
  failures with exact errors.
